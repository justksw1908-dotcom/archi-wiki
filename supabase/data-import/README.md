# 기존 프로토타입 위키(1104개 문서) 이식

`wiki-전체.html` 프로토타입에 이미 만들어둔 0장~6장 전체 문서를 AI 재생성 없이 그대로 실제 Supabase DB로 옮기는 1회성 스크립트예요. Supabase 대시보드 → SQL Editor에서, 아래 순서 그대로 하나씩 새 쿼리 창에 붙여넣고 실행하세요. (한 파일 끝나면 다음 파일 — 전부 합쳐서 한 번에 실행하지 마세요.)

## 실행 순서

1. `00_cleanup_ai_generated.sql` — 테스트 삼아 AI로 미리 생성해봤던 문서(및 관련 링크·승인대기)를 지워요. **AI 생성 문서가 하나도 없다면 이 파일은 건너뛰어도 돼요** (지울 대상이 없어서 그냥 0건 삭제되고 끝나요).
2. `ch0_wiki_pages.sql`(0장) → `ch1_wiki_pages.sql`(1장) → `ch2_wiki_pages.sql`(2장) → `ch3_wiki_pages.sql`(3장) → `ch4_wiki_pages.sql`(4장) → `ch5_wiki_pages.sql`(5장) → `ch6_wiki_pages.sql`(6장) — 장 순서 상관없이 실행해도 되지만, 번호 순서대로 하는 걸 추천해요. (파일명은 한글 대신 영문으로 만들었어요 — 압축·다운로드 과정에서 한글 파일명이 깨지는 경우가 있어서요.)
3. `07_wiki_links.sql` — **반드시 위 7개 장 파일을 전부 실행한 뒤에** 마지막으로 실행하세요. 문서 간 링크(1523개)를 연결해요. 이 파일보다 먼저 실행하면 아직 없는 문서를 참조하다 오류가 날 수 있어요.

## 확인

전부 실행한 뒤 Table Editor에서:
- `wiki_pages` 표에 1104개 행이 있는지 (좌측 하단 행 개수 또는 SQL Editor에서 `select count(*) from wiki_pages;`)
- `wiki_links` 표에 1523개 행이 있는지 (`select count(*) from wiki_links;`)

이 스크립트는 로컬 Postgres에 실제 스키마를 올리고 전체 과정(정리 → 이식 → 링크 연결)을 재현해서 최종 개수·중복 제목·깨진 링크가 없는 것까지 미리 확인했어요.

## 참고

- 이 문서들은 `source_chunk_id`가 비어있는 채로 들어가요(AI가 아니라 프로토타입에서 직접 옮긴 문서라는 뜻). 그래서 나중에 실수로 이 스크립트를 두 번 실행하면 같은 문서가 중복으로 생겨요 — 한 번만 실행하세요.
- 혹시 프로토타입 HTML의 "편집 잠금" 기능으로 브라우저에서 문서를 추가·수정하신 게 있다면, 그건 그 브라우저의 로컬 저장소에만 있어서 이 이식 스크립트엔 반영이 안 됐어요. 있으면 "내보내기"로 백업한 JSON 파일을 알려주시면 반영해드릴게요.
